# Openpaych CSS split — preparation only

## Что сделано

- `style.css` — копия исходного монолитного CSS. Файл сохранён без изменений.
- `styles/index.css` — подготовленная точка входа с импортами новых файлов. Она **не подключена** к приложению.
- `styles/shared/` — цветовые переменные, базовые правила, каркас/layout, повторно используемые стили, Markdown-оформление, responsive-правила и настройки доступности.
- `styles/components/` — стили повторно используемых UI-компонентов: шапки, модальных окон, карточек книг и статей, профиля автора, пагинации, уведомления о публикации и подвала.
- `styles/pages/` — стили, привязанные к страницам: лендинг, авторизация, профиль, сервисы, страницы базы знаний, чтение/редактирование статей и читалка.

## Почему структура такая

Общие переменные и правила вынесены в `shared`, чтобы не копировать цветовую палитру, типографику карточек, оформление Markdown и служебные классы между страницами. Селекторы конкретных элементов находятся в `components`, а сетка и стили, которые описывают целую страницу, — в `pages`.

Некоторые правила из монолита намеренно сохранены в тематических файлах, даже если ими пользуется более одного экрана (например, `.book-publication-notice` вынесен в отдельный компонент, так как он используется и на странице книги, и в читалке). Это делает дальнейшую миграцию явной и уменьшает риск случайного дублирования.

## Важное ограничение

Новые файлы пока не импортируются приложением. Действующий `style.css` не меняется и продолжает быть единственным подключённым источником стилей. Не подключайте одновременно `style.css` и `styles/index.css`: после будущей проверки миграции один источник должен заменить другой.

В исходном репозитории не предоставлены JSX/TSX/HTML-компоненты и конфигурация сборки, поэтому структура подготовлена как самостоятельный каталог `styles/`. Программисту нужно перенести каталог в согласованное место проекта и, на отдельном этапе миграции, заменить подключение монолита на `styles/index.css` после визуального сравнения страниц.

## Предлагаемая последовательность миграции позже

1. Убедиться, что `styles/index.css` доступен в текущей системе сборки (обычные CSS `@import` используются здесь без предположения о React/Vite/другом фреймворке).
2. В отдельном PR заменить подключение `style.css` на `styles/index.css`, не подключая оба файла одновременно.
3. Проверить основные страницы и адаптивные состояния на ширинах до 560 px, 760 px, 900 px и выше 1200 px, а также состояние `prefers-reduced-motion`.
4. Если визуальная проверка проходит, удалить монолит только в отдельном PR после подтверждения, что он больше нигде не импортируется.

## Состав стилей

- `shared/theme.css` — `:root`, переменные палитры и базовые настройки шрифтов.
- `shared/base.css` — reset-подобные базовые правила для `*`, `html`, `body`, `button`, ссылок.
- `shared/layout.css` — `.page`, `.container`, `.skip-link` и каркас страницы.
- `shared/utilities.css` — вспомогательные/доступностные стили.
- `shared/common-components.css` — кнопки и типографика, переиспользуемая карточками/элементами разных страниц.
- `shared/markdown-content.css` — стили Markdown-контента и состояния изображений.
- `shared/responsive.css` — имеющиеся media queries для планшетов и телефонов.
- `shared/reduced-motion.css` — `prefers-reduced-motion`.
- `components/book-publication-notice.css` — общее уведомление об условиях публикации книги.

Остальные файлы именованы по соответствующим компонентам или страницам.
